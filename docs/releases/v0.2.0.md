# THALIA v0.2.0

Release date in source metadata: **2026-11-08**. Versioned GitHub release URL:
<https://github.com/docxology/thalia/releases/tag/v0.2.0>.

The release's exact tag/commit, asset checksums, and exercised checks are recorded
in the GitHub release and its machine-readable release manifest. Version metadata
and these source notes are not independent proof of publication.

## Changes

- Optional common-backend benchmark using the same `AutoHarness`, configuration,
  metric, seeded synthetic cohort, and fresh per-example state across selected
  clients. Offline extractive, local Ollama, explicitly authorized OpenRouter,
  and caller-supplied `LMClient` backends share complete/failure accounting.
- Installed `thalia` query and `thalia-benchmark` commands. The benchmark CLI
  calls the existing evaluation backend; the source script remains a thin
  bootstrap. Its default `output/data/backend_benchmark.json` resolves from the
  caller's working directory, not the installed package.
- Isolated complete/incomplete benchmark outputs, validation, optional dashboard
  input, and source-bound manuscript reporting. Historical DSPy and provider
  diagnostic cohorts remain separate rather than pooled into matched results.
- Current citation/manuscript metadata identifies v0.2.0 on GitHub separately
  from the immutable v0.1.0 Zenodo archive. Manuscript DOI loading fails closed
  for missing, unreadable, invalid, or ambiguous historical archive metadata.

See the [benchmark guide](../backend_benchmark.md) for backend selection,
cloud opt-in, schemas, privacy/cost boundaries, and operational caveats, and
[release controls](../release_readiness.md) and the
[asset/provenance boundary](../release_artifacts.md) for publication gates.

## Evidence and limitations

This is a software and reproducibility release, not scientific promotion.
The benchmark is a finite synthetic diagnostic, not a general model ranking or
an expert correctness/faithfulness study. Automatic support metrics are not
entailment labels. Measured latency includes harness/client overhead and depends
on hardware, provider behavior, model revision, and warm-up. Live backends are
outside the deterministic core's reproducibility envelope.

The default extractive Reasoner bounds answer generation; the hashing semantic
lane is a surrogate, not a learned dense retriever. Independent P0 integrity,
expert-rater quality, and production-readiness acceptance are not established
by benchmark completion, artifact validation, or release publication.
Historical tests/renders are not source-current v0.2.0 receipts. Release validation
regenerates and inspects the versioned manuscript, PDF, HTML, and slides; the
release manifest records the observed final-candidate results.
