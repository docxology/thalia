## Offline planning before real inference

`thalia-benchmark --plan` prints a JSON workload and exits without model metadata
probes, credentials, completions or report writes. It shares the deterministic
cohort and rotated schedule with execution and validation. The plan includes
selected backend/method identities, examples, analysis settings, execution order,
ordered cells and counts. `counts.planned_attempts` is the complete matrix;
`counts.planned_pairs` is zero if the selected reference is absent. These are
planned bounds, not successful observations, billed tokens, latency or price.

```bash
thalia-benchmark --plan --ollama-model gemma3:1b \
  --method full_context --method harness --method lexical_only \
  --method adaptive --seed 0 --seed 1 --seed 2 --per-category 2
```

Remove `--plan` only when real inference is authorized. Cloud model selection
still requires explicit `--allow-cloud`; a plan itself sends no prompts. Python
callers use `src.evaluation.backend_benchmark.build_benchmark_plan`. Full-context-
only selection ignores unused base harness verification settings; selecting a
harness-derived method still requires `verify=False`.
Installing the optional SDK does not opt a deterministic import into DSPy or
LiteLLM's remote pricing lookup. The real signature bridge imports DSPy only when
explicitly called; model metadata adapters retain their separate lazy boundary.

## Visible per-seed contributions

`src.evaluation.benchmark_analysis.summarize_seed_pairs` derives audit rows from
validated schema-2 observations without changing their bytes or schema. Dashboard
and manuscript tables show backend, method, represented seed, requested/complete
pairs, wins/ties/losses, mean delta and status. Any missing pair suppresses that
seed's mean, including zero surviving pairs. Complete seeds never rescue an
incomplete whole contrast. The whole complete estimand weights seed means equally;
pooled successful-example means can use different weights.

This adds inspectability, not observations, independence, population precision,
new resampling, significance tests or expert answer labels. The original study's
small seed count and repeated-input limitations remain visible.

## Coherent runtime composition and cleanup

`AutoHarness` retains the actual executing stage graph. Its exposed Reasoner and
Retriever are not dormant copies; stage customization affects subsequent turns.
Fresh compiler examples and benchmark cells retain isolated harness/store state.
Inspector adaptive policy remains configuration-driven.

Pipeline diagnostics copy built-in state and the extras mapping, but preserve
opaque extras values by identity. Open files, generators and connections remain
caller-owned and are neither copied nor closed. Nested custom values remain
shared; this is not a promise of immutable snapshots for arbitrary objects.

`Session.close()` closes SQLite even if derived MEMORY.md persistence fails.
Persistence errors propagate, with ordinary Python chaining preserving an earlier
context-body error. Disk-backed `reset()` reopens retained episodes, never deletes
append-only history. The query helper also uses explicit context-managed cleanup.

The query CLI accepts `--no-verify`, `--no-query-expansion`, `--no-recall-memory`
and `--no-adaptive-windows`. Negative flags override enabled file/environment
settings; omitted flags preserve the inherited choice. Disabling verification
prevents its optional additional completion.

## Truthful and coherent publication evidence

Empty JUnit collection cannot PASS on the strength of coverage alone. Current
malformed/partial test reports invalidate the observation instead of retaining
old PASS/counts. Counter consistency and finite coverage are checked. Preserved
historical observations with both source reports absent are not a new execution;
warning policy must come from the actual exercised command.

Both consumer generators write input receipts binding their final artifact and
selected benchmark raw bytes/fingerprints/status. The release gate requires the
same portable staged evidence and current artifacts. It rejects divergent valid
reports, external-only selections, missing evidence and subsequent mutation.
External standalone inspection is allowed; nothing silently copies or reseals
observations to make publication pass. Authored nonblank figure descriptions now
reach dashboard image alt text independently of visible source captions.

`src.release_artifacts.assemble_release_artifacts` and its thin CLI assemble only
an explicit reviewed file allowlist from an already frozen stage. They require
THALIA's required-source contract and all output members referenced by either
inventory, retain exact inventory bytes, produce deterministic tar/gzip metadata
and refuse missing/unsafe/symlinked/changed members or destination replacement.
The member receipt attests bytes/closure only: native validation remains a separate
real owner-run gate. See [artifact assembly](../release_artifacts.md).

## Qualification and use

Use the current wheel's `thalia` and `thalia-benchmark` outside a checkout without
the optional SDK. Review the plan before real local inference, explicitly select
the same staged report for both publication consumers, then finish all source,
rendering, browser/QA and frozen native/project gates before archive assembly.
No allowlist pruning or manifest-tracked mutation follows final validation.

The release provides package distributions, exact tagged source, combined PDF,
curated supplement, unchanged primary backend JSON, release manifest and checksums.
Verify all downloaded assets with `shasum -a 256 -c SHA256SUMS`. The exact merged
Git tree must match the qualified candidate; source availability and software
checks do not close scientific tasks in the native backlog.
